F. Learnings & Key Insights

F.1 — Critical Learning: Angular p-autocomplete After Copy/Edit

RULE: After a Copy or Edit operation, Angular p-autocomplete fields display chips with correct values. DO NOT attempt to re-select these values — they are already bound internally. Re-selecting breaks Angular's internal form binding and causes the form to become invalid.

Pattern: After Copy/Edit, only modify fields that need NEW values (e.g., amount). Leave pre-filled autocomplete fields untouched.

Applies to: All test cases that use Copy or Edit operations (ICT, ACT, TT, etc.)

F.2 — Learning: Checkbox State Inheritance After Copy

RULE: When a payment is copied, checkbox states (like "Transaction Note") are inherited from the source. Always check isChecked() before calling toggleAngularCheckbox() — otherwise you'll uncheck an already-checked field.

Pattern:

const isChecked = await checkbox.isChecked().catch(() => false);
if (!isChecked) {
  await webComponents.toggleAngularCheckbox(page, label, checkbox);
}

F.3 — Learning: Variable Scoping in Multi-Phase Tests

RULE: When the same UI element (e.g., "Earliest available date" radio) appears in multiple phases of a single test, use distinct variable names per phase (e.g., earliestDateRadioSrc, earliestDateRadioCopy) to avoid const redeclaration errors.

F.4 — Learning: Protractor Source Is Ground Truth for Copy/Edit Flows

RULE: For Copy/Edit test cases, always reference the original Protractor source to determine which fields are touched after the operation. The Protractor test represents the minimal working flow. Adding extra interactions (like re-selecting accounts) can break Angular's state management.

Protractor TC07 sequence after Copy: copyButton.jsClick() → jiazhai() → amount.qingChu() → amount.ShuRu(amountV) → jiazhai() → nextButton.click()

Playwright TC007 equivalent: javaScriptsClick(copyButton) → waitForCopyReady() → amount.click() → amount.fill('') → enterTextarea(amount, value) → waitForUXLoading → clickWhenVisibleAndEnabled(nextButton)

F.5 — Learning: Message to Approver = Transaction Note

Clarification: In the ICT module, "Message to your Approver" is the same as the transactionNote textarea (//textarea[@name="transactionNote"]). The test data value used is IntraCompanyTransfer.additionNote = "messageToOrderingBank". On the View page, it displays via #ict-view-transactionNote (aliased as messageToApproverValue in the page class).
