💡 Key Learnings & Patterns

1. ShuRu Component Replacement (Global Pattern)

Pattern: All ShuRu[@name="..."] and ShuRu[@formcontrolname="..."] locators across ALL payment types are broken in current UI.

Solution: Replace with native element selectors → input[name="X"], textarea[name="X"], label[for="X"] (checkboxes)

Files Updated: learnings.md (documented for future migrations)

2. Radio Button State Verification (Hidden Display)

Pattern: Form elements can be CSS-hidden but DOM-present. Standard visibility checks fail.

Solution: Use evaluate() to check element attributes (disabled, aria-disabled) independent of CSS visibility

Code Pattern: Direct attribute evaluation instead of toBeVisible() checks

3. Angular Checkbox Click Pattern (Label Click)

Pattern: Angular wraps checkboxes inside custom components; actual input is hidden

Solution: Click visible label element to toggle hidden checkbox

Verification: Verify checked state and implement retry loop (up to 3 attempts)

4. Page Object Model Pattern (webComponents Only)

Pattern: All locators in page class; no in-memory locators in spec files

Solution: Use lazy getter pattern for locator definitions; interact via webComponents utilities

Benefit: Centralized maintenance, consistent logging, built-in retries
