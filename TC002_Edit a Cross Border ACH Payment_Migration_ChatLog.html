Section F — Key Learnings (TC002)

  1. Edit form reuses same locators: The payeeAmount locator (//input[@name="payeeAmount"]) works identically on both the create form and edit form. No separate "edit mode" locators needed.
  2. Reference ID does NOT change after edit: The same reference number is returned on the submitted page after editing. The referenceEdit || reference fallback pattern is useful but both values are identical.
  3. Clear + fill pattern: For editing pre-filled numeric fields, use .click() → .fill('') → enterTextarea(). The fill('') clears the existing value reliably.
  4. waitForFormReady() works on edit: The same form-ready detection logic handles both empty (create) and pre-filled (edit) forms without issues.
  5. TC001 learnings transfer directly: Because TC002's create phase is identical to TC001, all TC001 learnings (pagination dots, autocomplete, intermediary bank, message-to-payee checkbox) applied directly with zero rework.
  6. Consistent timing: The full 5-phase flow (Create → Validate → Edit → Validate → Delete) completes in ~2.1 minutes, only slightly longer than TC001's ~1.8 min (create + delete only).
  7. Edit flow structure: Edit button → waitForFormReady → modify fields → Next → Preview → Submit → Submitted — same submission pipeline as create.
