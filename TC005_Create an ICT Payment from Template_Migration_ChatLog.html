Root Cause: Used javaScriptsClick(logoutButton) from the template submission confirmation page. The logout button was not clickable — page overlay or DOM state blocked the click.

Self-Fix Applied: Changed approver user from 'SPI307R02' to 'DBSAUTOSGICT02' per user instruction.

Run 2 — FAILED (timeout ~5 min)

Error: Same hang — template created but logout never completed.

Diagnosis: javaScriptsClick(logoutButton) executes evaluate(el.click()) which silently fails if element is obscured.

Self-Fix Applied: Added finishButton click before logout attempt to dismiss the submission confirmation overlay.

Run 3 — FAILED (timeout ~5 min)

Error: Hung on waitForUXLoading() after finishButton click.

Root Cause: finishButton click on submission page does NOT trigger a UX loading spinner. waitForUXLoading() waits indefinitely for a spinner that never appears.

Self-Fix Applied: Removed waitForUXLoading() after finishButton. Changed approach to javaScriptsClick(paymentMenu) → waitForTimeout(MODERATE) → javaScriptsClick(logoutButton).

Run 4 — FAILED (timeout ~5 min)

Error: Still hung — paymentMenu click from submitted page didn't navigate. Login fields not found after attempted logout.

Diagnosis: The submitted page's DOM state prevents reliable navigation via menu clicks. All approaches using logoutButton or menu navigation from the submitted page are unreliable.

Self-Fix Applied (BREAKTHROUGH): Replaced entire logout pattern with loginPage.goto() — navigates directly to the SIT login URL, implicitly ending the session. This is the same pattern used successfully in other multi-user flows.

Run 5 — FAILED (3.0 min) — Progress: Template approved ✅

Root Cause: Amount field value "5,100" (from testData.IntraCompanyTransfer.SIT.amountV) contains a comma. The input field does not accept commas — form validation prevented navigation to preview page.

Self-Fix Applied: Changed amount from testData.IntraCompanyTransfer.SIT.amountV ("5,100") to hardcoded '5100'.
