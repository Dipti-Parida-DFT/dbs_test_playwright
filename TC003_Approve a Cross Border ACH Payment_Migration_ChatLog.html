Section F — Key Learnings (TC003)

  1. Digital token section is collapsed: After clicking the Approve button, the M-Challenge/SMS section is hidden behind "Alternatively, use your digital token or security device for approval". Must click pushOption to expand before getChallengeSMS becomes visible.
  2. Approved payments cannot be deleted: The Delete button is intentionally disabled on approved payment view pages. Do NOT include delete cleanup for approve test cases.
  3. Approve locators live on AccountTransferPage: Use viewPageApproveButton (button[name="approve"]:not(#push-btn)), getChallengeSMS, challengeResponse, dismissButton, pushOption from AccountTransferPage.
  4. Approve flow sequence: viewPageApproveButton → pushOption (expand) → getChallengeSMS → challengeResponse (CHALLENGEVIASMSCODE) → wait enabled → viewPageApproveButton → dismissButton
  5. Use CONSTANTS.CHALLENGEVIASMSCODE: The challenge code is '12345678' per constants, NOT the test data responseCode: "123".
  6. Two approve buttons on view page: #push-btn ("Approve now" for mobile push, may be disabled) and the toolbar Approve button. Use viewPageApproveButton (:not(#push-btn)) to target the correct one.
  7. crsBrdTransactionStatusValue: Uses #crsbrd-view-pendingStatus_0 — works for both "Pending Approval" and "Approved" status values on the CrossBorder view page.
