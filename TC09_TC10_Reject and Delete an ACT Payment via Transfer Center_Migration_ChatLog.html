Design Decisions

  • Self-contained test: Protractor TC09/TC10 depended on payment created by prior serial TCs. Playwright version creates its own ACT payment in Phase 1, then rejects, validates, deletes, and validates in one test block.
  • Combined TC09+TC10: Merged into a single 5-phase test since TC10 (delete) operates on the same payment that TC09 rejects — they must run sequentially on the same transaction.
  • Amount selection: Uses amountA1 ("10") with existing payee — small amounts skip verification and land in "Pending Approval" status where Reject is enabled.
  • BulkPaymentPage locators for reject dialog: AccountTransferPage.reasonForRejection uses broken ShuRu[@name] pattern. Used BulkPaymentPage.reasonForRejection (input[@name="reasonForRejection"]) instead.
  • Shared delete helper: Reused PayrollPage.deleteOpenPayeeOrReferenceNo() for the delete dialog — same shared component across payment modules.

Test Flow (5 Phases)

  • Phase 1 — Create ACT Payment: Navigate → Auth → Transfer Center → Make Payment → Existing Payee → Amount (10) → Next → Submit → Capture reference
  • Phase 2 — Reject Payment: Navigate to Transfer Center → Search by reference → Open view page → Scroll to bottom → Click Reject → Enter reason → Confirm reject → Capture rejected ref → Dismiss dialog
  • Phase 3 — Validate Rejected: Navigate to Transfer Center → Search by reference → Open view page → Assert status = "Rejected"
  • Phase 4 — Delete Payment: Call deleteOpenPayeeOrReferenceNo() → Dismiss "Transaction deleted" popup
  • Phase 5 — Validate Deleted: Navigate to Transfer Center → Enter reference in filter → Assert "No information to display"
